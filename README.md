# Introduction to Data Analysis Using Pandas

Pandas is one of the most widely used Python libraries in data science, yet many learners skip past the fundamentals and end up confused later. This repository works through data manipulation from the ground up - constructing DataFrames from raw Python objects, selecting data with precision using label-based and position-based indexers, reading and writing structured files, and running a full exploratory analysis pipeline on real-world datasets. By working through the main notebook and the accompanying homework, you build the muscle memory needed to handle real data confidently.

---

## Learning Objectives

- Construct Pandas DataFrames from 1D arrays, 2D arrays, Python dictionaries, and Series objects
- Access and modify data using label-based (`.loc`) and position-based (`.iloc`) indexing
- Rename, drop, and overwrite columns and rows without accidentally modifying the wrong copy
- Read tabular data from CSV and Excel files into DataFrames
- Explore and summarize a dataset using `.info()`, `.describe()`, `.groupby()`, and `.sort_index()`
- Write transformed data back to CSV and Excel formats
- Clean a real-world dataset by handling missing values and duplicates
- Compute derived columns (such as GDP per capita) and pivot data using `.unstack()`
- Recognize when a column is a Series and use that to your advantage when combining sources

## Step-by-Step Walkthrough

### Part 0 - About and Motivation

Before loading any data, the notebook frames why Pandas matters: real-world data arrives as CSV files, Excel sheets, API responses, or database dumps - each with its own quirks. Pandas provides a single, consistent interface to load, inspect, reshape, and summarize all of them. The core abstraction is the DataFrame: a two-dimensional table where both rows and columns carry labels, which means the data knows what it represents, not just what values it holds.

### Part 1.1 - The Pandas DataFrame

The notebook introduces the DataFrame as a labeled, two-dimensional data structure. Unlike a plain NumPy array, a DataFrame knows what its columns mean. Unlike a Python dictionary, it aligns data by label when you combine multiple sources. This section lays the conceptual groundwork so that later API choices - why `.loc` instead of plain bracket indexing, why `inplace=True` matters - are motivated rather than arbitrary.

### Part 1.2 - DataFrame Creation

The notebook then asks the most basic question: how do you get data into a DataFrame in the first place? Three paths are shown in sequence. First, a 1D NumPy array is passed to the constructor, which produces a single-column DataFrame with an auto-generated integer index. Next, a list of arrays is passed, producing a multi-column DataFrame - and then column names and a custom index are added to show how labels are assigned after the fact. Finally, a Python dictionary is used, where the keys become column names automatically. This progression from shape-only to labeled to semantically meaningful is deliberate: it mirrors the progression from raw data to analysis-ready data.

The Series object is introduced here as the building block of a DataFrame. Each column in a DataFrame is a Series with its own index. When you add a Series to an existing DataFrame, Pandas aligns by index - so if indices do not match, the result is `NaN` in the misaligned positions. Seeing this happen once in code is clearer than reading a description of it.

### Part 1.3 - Accessing the DataFrame

The notebook covers three levels of data access. Basic bracket indexing retrieves columns by name and rows by slice. Range slicing with negative steps and step sizes shows how Python slice semantics extend to DataFrames. The section then argues, through a concrete example, that chained bracket indexing gets confusing quickly, and introduces `.loc` and `.iloc` as the preferred alternatives.

`.loc` is label-based: `df.loc['c':'e', 'B':'D']` selects rows `c` through `e` and columns `B` through `D`, inclusive on both ends. `.iloc` is position-based: `df.iloc[2:5, 1:3]` selects rows at positions 2, 3, and 4 and columns at positions 1 and 2, following Python's exclusive-end convention. The distinction matters because Pandas will silently return an empty result rather than raise an error if your labels do not match - which is a source of hard-to-find bugs in analysis code.

The section closes with a concept check that asks you to select the same region using both `.loc` and `.iloc` and verify the results match using `.equals()`. Writing the comment explaining why `.loc['b':'d']` includes `'d'` while `.iloc[1:4]` does not include position 4 forces you to articulate the difference in your own words.

### Part 2.1 - Reading Data and Exploring

Reading from CSV is the most common entry point for real data. The notebook uses the UCBAdmissions dataset because it has enough structure - multiple categorical columns and a numeric frequency column - to make `.groupby()` operations meaningful. You see `.groupby()`, `.sum()`, and `.plot.bar()` in sequence, each building on the last to go from raw data to a visual summary in a few lines.

The exploration methods - `.info()`, `.columns`, `.head()`, `.tail()`, `.describe()` - are not just diagnostic tools. `.info()` reveals whether a column is stored as an object (string) when it should be numeric, which is one of the most common causes of silent errors in aggregations. `.describe()` gives a fast distribution check that often surfaces data quality issues before any deeper analysis begins.

### Part 2.2 - Writing Data to CSV

The write section demonstrates filtering a DataFrame to a subset (Department A applicants), writing it to CSV with `index=False`, and reading it back as a sanity check. The `index=False` argument is highlighted because omitting it adds an unnamed column of row numbers to the output file - which then becomes an extra column on the next read.

### Part 2.3 (Optional) - Reading and Writing Excel Files

The Excel section is marked optional because `openpyxl` and `xlrd` are additional dependencies. The section still runs end-to-end and demonstrates transposing a DataFrame with `.T`, which swaps rows and columns. The transposed result is then written to a new `.xlsx` file. This is a useful operation regardless of file format and illustrates that DataFrames can be reshaped before writing.

### Homework - Preprocessing, EDA, and Generalization

The homework notebook applies the same Pandas foundations to two datasets that require more preparation than the clean UCBAdmissions data. The FAO water resource dataset (GDP, NRI, population density, total area, total population by country and year) contains missing values, duplicate rows and columns, and mixed types. Working through this dataset forces you to use `.dropna()`, `.drop_duplicates()`, `pd.to_datetime()`, and `inplace=True` in a realistic context where the order of operations matters.

The statistical analysis section pivots the data using `.unstack()` after a groupby to produce a wide-format DataFrame where each variable becomes its own column. A GDP per capita column is then derived using arithmetic on two existing columns. These two operations - reshaping with unstack and computing derived columns - appear constantly in real analysis pipelines.

The final section uses the Iris dataset from scikit-learn to confirm that the skills transfer. Loading a new dataset, running `.info()` and `.describe()`, grouping by species, filtering by a numeric condition, and writing to CSV are all repetitions of the same pattern with no scaffolding. If you can complete this section without referring back to the main notebook, the fundamentals are solid.

## Key Concepts Glossary

| Term | Definition |
|------|-----------|
| **DataFrame** | A two-dimensional, labeled data structure - think of it as a spreadsheet with named rows and columns that lives in memory |
| **Series** | A one-dimensional labeled array; every column in a DataFrame is a Series, and aligning Series by index is the mechanism behind many Pandas operations |
| **Index** | The row labels of a DataFrame or Series; can be integers, strings, or datetimes; Pandas uses the index to align data when you combine sources |
| **`.loc`** | Label-based indexer - selects rows and columns by their names; the end label is inclusive |
| **`.iloc`** | Position-based indexer - selects rows and columns by their integer position; the end position is exclusive, following Python slice conventions |
| **`read_csv()`** | Reads a comma-separated values file and returns a DataFrame |
| **`groupby()`** | Groups rows by the values in one or more columns so that aggregations (sum, mean, count) can be applied per group |
| **`describe()`** | Returns summary statistics (count, mean, std, min, max, quartiles) for numeric columns - useful for a quick distribution check |
| **`dropna()`** | Removes rows (or columns) that contain missing values; the `subset` parameter lets you target specific columns |
| **`inplace`** | Parameter that, when set to `True`, modifies the DataFrame directly rather than returning a modified copy; forgetting this is a common source of silent bugs |
| **`NaN`** | "Not a Number" - Pandas's representation of a missing value; appears automatically when indices do not align or when source data has gaps |
| **`.T`** | Transposes a DataFrame, swapping rows and columns |
| **`unstack()`** | Pivots the innermost level of a row index into columns, converting long-format grouped data into a wide-format table |
